MacOS-Performance-Tweaks

boost_macos_performance.sh · 376 lines · one file does everything

Do not run this script as written

That is my own warning, it stands at the top of the script and the top of the README, and this page keeps it where it belongs: first. The script deletes logs, caches, and the contents of the Trash, deletes local Time Machine snapshots and then turns Time Machine off, runs fsck -fy on the live disk it is running from, changes boot arguments and kernel limits, rewrites DNS servers, and rebuilds indexes. It will most likely break your system. It is kept here as a research draft, a record of what I wrote and what I later found wrong with it, not as something to use.

Nothing on this page runs it. This page documents it, the way you would document a machine behind glass.

Entry 02

The gate: every destructive step asks, by name

The fix this file needed most was not speed. It was a pause. Ten steps in the script cannot be undone, and each one now stops and asks the person at the keyboard to type YES, in full, for that one step. Any other answer skips the step. Typing YES once approves nothing later; the question is asked again at every gate. Entry 05

What the rest of it does, ungated

The gates cover the steps that delete or disable. They do not make the rest of the script safe, and this page will not pretend otherwise. The ungated sections write Finder, Dock, Mission Control, and Safari settings (36 defaults write lines in all), set power and hibernation options, purge memory, vacuum the Mail and Photos databases in place, hardcode DNS to 1.1.1.1, 1.0.0.1, 8.8.8.8, and 8.8.4.4 on the Wi-Fi service, turn IPv6 off on Wi-Fi while setting a 9000 MTU on en0, raise kernel limits with no read-back afterwards, rebuild the Spotlight index, and restart Finder and Dock. The script has no error handling: no set -e, and almost no command checks its result, so a failure halfway down does not stop the deletions near the end. Its output is a log of attempts, not a record of what took effect.

The cleanup pass also removed duplicate settings that had crept in over edits: a second expose-animation-duration, a second autohide-delay, a second NSWindowResizeTime, a plain debug menu line superseded by its -bool true form, and a second mDNSResponder restart. Commands that are leftovers from older macOS releases, like repair_packages and repairPermissions, are left exactly as written and covered by the warning, not silently rewritten into something I have not tested either.

The ten gates

Each of these steps stops and asks for a typed YES for that step alone, in this order:

  1. Turn off the LaunchServices quarantine prompt for downloaded apps
  2. Delete local Time Machine snapshots
  3. Delete the sleep image, language and speech data, suggestions, Quick Look data, help caches, and log files under Application Support and Containers
  4. Delete all system logs and user logs
  5. Delete temporary files and all user caches
  6. Clear font caches and delete the font cache folders
  7. Turn Time Machine off and turn local snapshots off
  8. Empty the Trash and delete its contents for good
  9. Run fsck -fy on the live disk this script is running from
  10. Delete system caches under Library, System Library, and your home folder
