Vestry notice, read first: what cannot be undone

Do not run this script as written. It will most likely break your system. In plain words, boost_macos_performance.sh:

  • Turns off the LaunchServices quarantine prompt, the dialog macOS shows before you open an app you downloaded.
  • Deletes local Time Machine snapshots, then turns Time Machine off, including local snapshots, so no local backup is left on the machine.
  • Deletes the sleep image, language and speech data, system logs, user logs, temporary files, caches, font caches, and the contents of the Trash. None of it can be brought back.
  • Runs fsck -fy on the live disk the script itself is running from.

Each of those steps now stops and asks you to type YES for that step before it runs. Any other answer skips that step, and typing YES once does not approve any later step. The gates do not make the rest of the script safe. It is preserved here as a research draft, not as a recommended tool.

MacOS-Performance-Tweaks

One script, boost_macos_performance.sh, and the order in which it does its work. The warning above stays first on this page, as it does in the README, because the script's deletions and shutdowns cannot be taken back.

First, what the script removes

Item by item: local Time Machine snapshots (gone for good once deleted), the sleep image, language and speech data, system logs, user logs, temporary files, caches and font caches, and the contents of the Trash. It also vacuums the Mail and Photos databases, clears logs and caches in its later sections, and rebuilds the Spotlight index. Losing the logs and caches means losing the record of what the machine was doing, not just the files themselves.

Second, what it switches off

Time Machine, named plainly: after this step there is no local backup history until Time Machine is turned back on and a fresh backup completes. It also turns off the LaunchServices quarantine prompt, changes DNS servers on Wi-Fi to 1.1.1.1, 1.0.0.1, 8.8.8.8, and 8.8.4.4 and disables IPv6 on Wi-Fi, changes boot arguments, kernel limits, and power settings, and sets Finder, Dock, Safari, App Store, iCloud, and menu bar options across its sections.

Third, how to run it, and how to read it first

bash -n boost_macos_performance.sh

That syntax check passes. Reading the script first means reading the warning header, then each gated step, then the sections in order: UI and Finder tweaks, Safari settings, memory and power, CPU and GPU kernel settings, disk and Time Machine commands, network settings, and the deletion sections. The script was not run live in the fixing pass, by design.

Fourth, what can be restored, and what cannot

Settings can mostly be set back: Time Machine can be turned on again, DNS and power settings can be rewritten, Finder and Dock options can be reset. What cannot be restored: deleted snapshots, logs, caches, the sleep image, and Trash contents. No fresh backup exists until a new one completes after Time Machine is back on.
