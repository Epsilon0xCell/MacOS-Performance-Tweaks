MacOS-Performance-Tweaks

Performance tweaks for macOS, in boost_macos_performance.sh.

Warning: do not run this script as written

My own warning stands, and this page keeps it first: do not use this script. It will most likely break your system, and further research is needed before any part of it is trusted. It deletes logs, caches, and trash contents, disables Time Machine local snapshots, runs fsck -fy on the live disk, changes boot arguments and kernel limits, rewrites DNS servers and network settings, and rebuilds indexes. It is preserved here as a research draft, not as a tool I recommend. Nothing in the improvement passes makes it safe to run, and this manual is a description of the script, not an invitation.

What this is

I collected every macOS tuning command I had gathered into one bash script, section by section, each section announcing itself with an echo line as it runs. Read as a list of settings, it is a fair record of what people tweak: Dock timing, Finder animations, Safari delays, hibernation, kernel limits, DNS. Read as a program, it is a draft with no brakes. There is no set -e and almost no command checks its result, so a failure halfway down does not stop the deletions near the end. The output is a log of attempts, not a record of what took effect.

I keep the repo because the list itself is useful to study and because the fixes the campaign made to it are worth showing. But the honest summary is the warning above. If a single entry below interests you, the entry is a starting point for your own research on that one setting, never a reason to run the whole file.

The entries, in the order the script runs them

01

The root gate

The script checks $EUID first and refuses to continue without root, printing "Please run as root (using sudo)". In Wave 5 I fixed what that refusal returned: it used to exit with status 0, so a refused run looked successful. It exits 1 now.

02

System animations and UI

Window, Dock, and Mission Control animation timing, Dock autohide delay, Dashboard off, CrashReporter dialog set to none, smart quotes and smart dashes off, and automatic restart on freeze. This section also turns off the "Are you sure you want to open this application?" dialog (LSQuarantine false). That prompt is a real safety check on downloaded apps, not decoration, and trading it away is one reason the warning sits at the top of this page.

03

Finder

Finder animations off, POSIX path shown in the title, list view as the preferred style, and the extension-change and empty-trash warnings off.

04

Safari

Three WebKit layout delay values set to 0.25. Later sections add Safari debug settings: the internal debug menu and developer extras, under the security entries.

05

Memory and power

purge, the daily, weekly, and monthly periodic jobs, then pmset changes: hibernation mode 0, sudden motion sensor off, Power Nap off, proximity wake off, and TCP keepalive off.

06

CPU, GPU, and the first boot-args write

An nvram write adding npci=0x2000 to boot-args, and two timer coalescing sysctls set to 0. A boot-args write replaces the whole string, so this line re-reads the current value and carries it forward. That re-read pattern matters again at entry 11.

07

Disk and Time Machine snapshots

An APFS defragment status probe per volume, gated on FileVault's fdesetup answering at all, then tmutil deletelocalsnapshots / and diskutil repairVolume /. The local snapshots go here, near the top, long before entry 14 turns Time Machine off outright.

08

Mail and Photos databases

SQLite vacuums run in place: the Mail envelope index (found through a V* path glob that a macOS update can move) and every .db under the Photos library. If Mail or Photos is running and holds the database locked, the vacuum fails and, with no error handling, nobody sees it.

09

Network, first pass

TCP delayed ack off, larger receive and send spaces, and DNS hardcoded to 1.1.1.1, 1.0.0.1, 8.8.8.8, and 8.8.4.4 on the service named "Wi-Fi". On a Mac where that service is named differently, or that is on Ethernet, this fails quietly.

10

System integrity, and the Gatekeeper entry

This is the safety entry of this manual, so I will state it exactly. Under the system integrity section the script runs sudo spctl --master-enable: Gatekeeper is switched on, not off. An earlier version of this script ran spctl --master-disable under a security heading, turning a protection off while claiming to add one. Wave 5 reversed that line, and the script's own final line then asks for a restart so the changes take effect: "Please restart your Mac for all changes to take effect." Protection is re-enabled and left enabled; nothing in the current script turns it off. The same section runs the leftover repair_packages verify, a command from older macOS releases that is gone or refuses on a current system, and prints the SIP status with csrutil status.

11

Deep cleanup, logs, and caches

The point of no return in this script: the sleep image, language and speech data, suggestions, Quick Look support files, and help caches are deleted with no trash, no confirmation, and no list kept. Log files under Application Support and Containers follow. Later sections delete system logs, temporary files, and all of ~/Library/Caches, more than once.

12

Menu bar and the security settings section

The menu extras list is set to Bluetooth, Volume, Battery, and Clock. The section headed "Security Optimizations" writes two com.apple.security values, GKAutoRearm false and RSAMaxKeySize 8192, next to the Safari debug settings. I list what the section contains; the heading is the script's, and entry 10 is where the Gatekeeper fact lives.

13

Kernel limits and the second boot-args write

A second nvram write adds serverperfmode=1, and its re-read of the current boot-args is the only reason the npci=0x2000 flag from entry 06 survives; a fresh literal string here would silently drop it. Kernel limits follow: kern.maxvnodes 750000, kern.maxproc 2500, kern.maxfiles, and a launchctl file limit. None of these values is read back afterwards, so a rejected limit and an applied one look identical in the output.

14

Indexes, permissions, Time Machine off, trash, disk check

Spotlight is rebuilt with mdutil -E /, disk permissions are repaired with a command modern macOS has retired, font caches are cleared, and Time Machine is disabled with tmutil disable and disablelocal. After this entry there is no local backup left to fall back on if a tweak above was a mistake. The trash is emptied with rm, Launch Services is rebuilt, the locate database is updated, and the script runs fsck -fy on the live disk.

15

Network, second pass, and service restarts

IPv6 is switched off on Wi-Fi while the MTU is set to 9000 on en0, which on a desktop Mac is usually Ethernet, not the same interface. A 9000 MTU only helps if the rest of the local network takes jumbo frames; if it does not, large transfers can stall instead of speeding up. The script ends by flushing the DNS cache, restarting Finder and the Dock, and printing the restart request quoted in entry 10.

Corrections on record

Three fixes from Wave 5, all checkable in the current file. The non-root refusal now exits 1 instead of 0 (entry 01). Duplicated settings were removed: the second expose-animation-duration, the second autohide-delay, the second NSWindowResizeTime, the plain IncludeInternalDebugMenu 1 (the later -bool true form is kept), and the second killall -HUP mDNSResponder in the cleanup block. And the Gatekeeper line was reversed from disable to enable (entry 10). Other destructive or obsolete commands, repair_packages, repairPermissions, and fsck -fy among them, were left exactly as written and are covered by the warning rather than silently rewritten into a different script.

How this script was checked

$ bash -n boost_macos_performance.sh
(no output: syntax OK)

That is the whole verification: bash -n, before and after the fixes, plus reading. The script was not run live in any pass, by design, because running it changes a real Mac's settings and deletes files, and the staging machine is Linux in any case. I did not execute it for this page either.
